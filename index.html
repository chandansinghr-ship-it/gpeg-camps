Authoritative Cloud Spanner schemas representing the GPEG Camps primary stateful storage layers.

-- Table: primary camp workflow state tracking CREATE TABLE gpeg_camp_cases ( case_id STRING(64) NOT NULL, agency_name STRING(256) NOT NULL, region_scope STRING(32) NOT NULL, -- EMEA, APAC, AMER product_area STRING(256) NOT NULL, current_stage INT64 NOT NULL, -- 1-Nomination, 2-Pre-Camp, 3-Execution, 4-Post-Camp, 5-Closed deck_type STRING(64) DEFAULT ("Standard Deck"), discovery_status STRING(32) DEFAULT ("Not Sent"), presenter_assigned STRING(128), bfm_uplift FLOAT64, feedback_score FLOAT64, recording_url STRING(MAX), recording_deleted_flag BOOL DEFAULT (false), closed_timestamp TIMESTAMP, recording_archived_flag BOOL DEFAULT (false) ) PRIMARY KEY (case_id); -- Table: operational SLA countdown tracker CREATE TABLE camp_sla_tracker ( case_id STRING(64) NOT NULL, sla_milestone STRING(128) NOT NULL, -- e.g., Discovery Pending, Escaped Q&A Pending due_timestamp TIMESTAMP NOT NULL, days_remaining INT64, is_breached BOOL DEFAULT (false), CONSTRAINT FK_SlaCaseId FOREIGN KEY (case_id) REFERENCES gpeg_camp_cases (case_id) ) PRIMARY KEY (case_id, sla_milestone); -- Table: interactive live session attendee queries CREATE TABLE session_q_and_a ( question_id STRING(64) NOT NULL, case_id STRING(64) NOT NULL, question_text STRING(MAX) NOT NULL, status STRING(64) NOT NULL, -- Escalated to PM, Resolved expert_answer STRING(MAX), resolved_timestamp TIMESTAMP, CONSTRAINT FK_QaCaseId FOREIGN KEY (case_id) REFERENCES gpeg_camp_cases (case_id) ) PRIMARY KEY (question_id); -- Table: audit records for operational compliance CREATE TABLE system_audit_logs ( log_id STRING(64) NOT NULL, log_timestamp TIMESTAMP DEFAULT (CURRENT_TIMESTAMP()), event_type STRING(128) NOT NULL, details STRING(MAX) ) PRIMARY KEY (log_id); -- Table: temporal stage metrics tracker for bottlenecks (UX Guidelines 1) CREATE TABLE case_stage_history ( history_id STRING(64) NOT NULL, case_id STRING(64) NOT NULL, stage_entered INT64 NOT NULL, entered_timestamp TIMESTAMP DEFAULT (CURRENT_TIMESTAMP()), exited_timestamp TIMESTAMP, duration_seconds INT64, CONSTRAINT FK_HistoryCaseId FOREIGN KEY (case_id) REFERENCES gpeg_camp_cases (case_id) ) PRIMARY KEY (history_id);

Pre-calculates both regional segments and global TOTAL values in a single high-performance SQL execution using UNION ALL.

-- Calculate active pipeline, warnings, and averages by region scope SELECT region_scope, COUNT(case_id) AS total_camps, COUNTIF(current_stage < 5) AS active_pipeline, COUNTIF(current_stage = 2 AND discovery_status = "Pending") AS missing_discoveries, ROUND(AVG(bfm_uplift), 1) AS avg_bfm_uplift, ROUND(AVG(feedback_score), 2) AS avg_csat_score FROM gpeg_camp_cases GROUP BY region_scope UNION ALL -- Pre-calculated global row appended to the same result set to optimize rendering performance SELECT "GLOBAL TOTAL" AS region_scope, COUNT(case_id) AS total_camps, COUNTIF(current_stage < 5) AS active_pipeline, COUNTIF(current_stage = 2 AND discovery_status = "Pending") AS missing_discoveries, ROUND(AVG(bfm_uplift), 1) AS avg_bfm_uplift, ROUND(AVG(feedback_score), 2) AS avg_csat_score FROM gpeg_camp_cases;

Automated data retention job designed for Spanner. Selectively deletes expired closed recordings (>90 days) while respecting Shared Drive exceptions.

-- Selectively purge expired recordings from Spanner on retention cron boot UPDATE gpeg_camp_cases SET recording_url = NULL, recording_deleted_flag = true WHERE current_stage = 5 -- Closed AND TIMESTAMP_DIFF(CURRENT_TIMESTAMP(), closed_timestamp, DAY) > 90 AND recording_archived_flag = false; -- Safe exclusion check

E2E Camp Lifecycle Guide

Stage 1: Nomination & Webhook Sync Admin

Simulate nominations inside the Cases Connect Sandbox. When a ticket is submitted, a webhook payload is dispatched to our backend database, dynamically instantiating a new camp record in the **Nomination** Kanban column.

Stage 2: Pre-Camp Preparation & Scheduling Organizer

Drag cards from **Nomination** to **Pre-Camp Prep** (or click *Kickoff*). In the scheduler modal, assign a Lead Presenter, choose a future date, select the platform, and kickoff the session. This automatically generates a customized pre-camp client-facing email draft.

Stage 3: Client Discovery Submission AM / Client

Click on the Agency Portal tab, verify the Case ID token using our Heuristic helper, and submit the Discovery Form. This action upgrades the camp status to **Discovery Received** and transitions the deck type from standard to **Customized Deck**.

Stage 4: Live Session & PM Escalation Presenter

Move the camp card into **In-Camp Execution**. Click the **Presenter Console** to display the customized dynamic slide streams and connections roll-calls. Presenters can type hard technical questions here and click **Escalate to PM**.

Stage 5: Technical Resolution & Follow-up PM / Admin

The Program Manager views the escalated questions inside the **PM Escalation Queue**, writes an authoritative answer, and click *Resolve*. Returning to the dashboard, you transition the card to **Post-Camp SLA** and dispatch the follow-up package containing the synced Q&A solutions!

Stage 6: Client Survey & Case Closure AM / Client

In the **Agency Portal**, the client submits their post-camp survey. This logs a high CSAT feedback score and average BFM Adoption Uplift, closes the camp, and recalculates the analytics charts in the **Performance KPI** tab automatically.
